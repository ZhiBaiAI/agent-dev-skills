# 渐进式 Agent 设计流程

这是团队的 L2 设计流程。它规定怎样把业务想法变成可验证的 Agent Starter Intent；不替代 Resolver 的技术决策。

## 先确定什么

依次确认：业务目标与成功标准、主要用户和交互、输入输出、外部副作用、数据边界、运行时长与触发方式、部署限制。只有会改变 Blueprint、安全边界、持久化或运维形态的问题，才需要单独追问。

## 每轮的输出

保持四项简短状态：已确认事实、唯一待确认问题、当前最小方案、风险或假设。不要把技术框架名称当成需求；已有团队约束必须写进 Intent 的 `constraints`。

## 选型原则

先选确定性函数或单 Agent，再根据明确需求增加 Tool Loop、工作流、持久化、并行或多 Agent。每个新增复杂度都要写明触发条件、替代方案和可验证收益。

## 设计完成条件

在创建项目以前，必须具备完整的 `agent.intent.yaml`、用户确认的生成预览，以及 `docs/design-record.md` 中的验收标准、风险和参考资料。最终 Plan 以 Resolver 输出为准。
