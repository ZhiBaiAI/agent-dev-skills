# ADR-0001: 技能优先的工具集形态（skill-first）

- **状态：** 已接受
- **日期：** 2026-09-10
- **背景：** 本仓库的前身以 CLI 生成管道的形式分发，已废弃该形态

## 背景

Agent 生态的工具与框架更新极快。以 CLI / 生成管道为中心的工具链要持续追版本：模板、完整性哈希、迁移条目——每次上游发布都要改，而这些改动只为追踪版本漂移存在。同时，现代 coding agent（Claude Code、Codex 一类）在给定纪律化指令与验证门槛时，已经能可接受地复现这些工具链行为。行业在收敛到「技能 + 官方脚手架 CLI + 增量 agent 编辑」的形态。

## 决策

1. **以覆盖 Agent 开发生命周期的技能集分发。**`skills/` 下七个技能，两个轴：用户调用的编排技能（`agent-design`、`agent-stack`、`agent-scaffold`、`agent-eval`、`agent-review`，按开发顺序执行）与模型调用的纪律技能（`security-gates`、`complexity-ladder`，被编排技能调用，从不自我编排）。
2. **版本适配交给官方命令。**骨架来自官方脚手架 CLI（`create-next-app`、`npm i`、框架 CLI），非交互式运行。本仓库不发布模板包、完整性哈希或迁移。
3. **确定性从生成转移到验证。**agent 直接写代码。确定性保证以两种形式存活：(a) 生成的项目必须通过自己的机器可检查成功标准（typecheck、测试、安全清单、退出码 0）才能交付；(b) 两个纪律技能把安全等级与复杂度阶梯编码为强制工作流步骤。
4. **知识库共享且版本化。**`knowledge/` 是唯一参考基座（案例、规则、选型、实践、标准）；技能按触发加载条目，不复制内容。

## 后果

- 可复现性减弱：相同输入可能产出不同（但都通过标准）的项目。回归检测从 golden 测试转为逐项目成功标准 + 可选的模型评测。
- 升级保护（AST merge、不覆盖合并）不在技能范围内；升级回退为 git diff 人工评审。
- 仓库本身是纯内容工作区：无运行时、无构建产物，CI 只做结构校验（SKILL.md frontmatter、knowledge 引用可解析）。
- 技能分发与版本化（marketplace、多宿主元数据）是开放跟进项；每个技能带 `agents/openai.yaml` 供 Codex 类宿主使用。
