# 安全门槛（SECURITY GATES）

以下任一触发都会激活一道门槛：**浏览器**、**shell**、**文件系统写入**、**外部 MCP**、**多智能体**、**外部凭据**、**数据库**、**队列**、**外部 API**。一道门槛从不阻塞需求；它让所需控制显式化、不可回避。

## 安全等级

给每个被触发的能力分类：

- **等级 1 — 自动。**无需特殊控制。纯模型调用、对静态输入的只读工具。
- **等级 2 — 建议。**AI 可以建议该能力；必须配套已验证的控制。例如带作用域密钥的外部 API、凭据已迁移的数据库。
- **等级 3 — 需批准。**浏览器、shell、多智能体、外部 MCP。这些不能悄悄加上：需要一次明确的用户决策，并带下面整套控制。

## 按触发条件的所需控制

| 触发 | 所需控制 |
|---|---|
| 浏览器 | 沙箱执行、域名白名单、网络策略 |
| Shell | 沙箱执行、命令白名单、不传递凭据环境变量 |
| 文件系统写入 | 路径范围限制、写入审计日志 |
| 外部 MCP | 服务器白名单、工具权限评审、凭据作用域 |
| 多智能体 | 每 Agent 工具范围、Agent 间消息审计 |
| 凭据 | 最小作用域密钥、密钥存储（绝不在仓库）、轮换路径 |
| 数据库 / 队列 | 网络策略、凭据作用域、备份/保留决策 |

## 强制点

1. **设计时**（`agent-design`）：Level 3 能力不得静默进入设计。明确它、点名控制、取得明确决策。
2. **生成时**（`agent-scaffold`）：触碰被门控能力的接缝，必须让它的控制随同一次变更一起交付——绝不允许“以后再补控制”。
3. **评审时**（`agent-review`）：验证 diff 里每个被门控能力都有控制，且是 *激活的*，而不只是被引入的。

## 失败语义

失败的控制必须失败即关闭：被挡的域名保持被挡、沙箱错误停止执行、过期的凭据绝不回退到更宽权限的凭据。绝不把控制失败降级成警告。

## 隔离模型（standard §10）

**沙箱决定技术上可能什么；批准决定何时才需要授权。**它们是两条独立的轴：

1. **默认限制**：默认限制文件系统写入范围与网络访问；按工具按资源使用最小权限凭据；隔离代码执行 / 浏览器 / shell。保护 `.git`、Agent 配置、技能、安全策略目录。“用户点过一次”绝不是永久授权——每个后果重大的动作各自单独守门。
2. **分离 Brain / Hands / Session**（standard §10.2）：模型层、工具执行层、状态/会话层分别可沙箱化、分别可扩大/缩小权限。
3. **把不可信数据分类为数据，绝不是指令**（standard §10.3）：web 内容、邮件、PDF/Office、工具输出、检索块、MCP 资源、外部 Agent 消息、用户上传的代码。阻止它篡改工具权限、系统提示词或批准策略；从它提取出的动作要重新验证；检查高风险工具参数是否有不可信来源。

## 逼出这些门槛的失败案例（lessons §7）

- **用户本身就是注入向量。**看似合理的请求在 24/25 次里把 Claude 引向窃取 AWS 凭据（7.1）。把敌意提示当作有界输入，而不是指令。
- **凭据绝不进入 Agent 的生成代码沙箱。**结构性隔离胜过分得更细的作用域；被攻破的沙箱也拿不到可用密钥（7.4）。
- **出口白名单会被攻击者控制的 API 密钥绕过**——一个产出完美结果的沙箱仍可能通过放行的出口泄露，如果目标/凭据链不是真正的控制点（7.7）。控制数据能流向哪里，而不只是什么能运行。
- **记忆投毒能穿透内容检查**：做写入时的来源绑定 + 后果重大动作前的动作门槛，而不是读取时检测（7.9；standard §10.8）。
- **批准疲劳真实存在**（>93% 在量上升时自动批准）。滥用会杀死门槛；保持自动化批准面小而后果重大（7.5、7.8）。

## 密钥与副作用（playbook §6）

- 密钥放在 env / 密钥存储里，绝不在 AGENTS.md、仓库、知识库或会话里。
- 高风险动作（受保护分支 push、force-push、skip-check、类 drop 命令、生产数据写入）在执行前被机械拦截——“Agent 说它会小心”不是控制。
- 有副作用的变更走 stage/apply，带绑定审批的 ID；环境跨回合变化时，不要基于过时前提重放。
- 超时不是失败：在副作用工具上，服务端可能已成功而客户端报错。重试前用请求 id 查状态；携带幂等键；限制重试与扇出；持续失败时熔断。

## MCP 安全基线（standard §11）

- 跨进程 / 跨语言复用或跨主机共享确属真实时优先 MCP；进程内函数、单项目内部与延迟敏感路径避免用它。
- HTTP MCP：正确的 OAuth 流、校验 audience 的 token、**绝不透传 token**、token 不进 URL、只走 HTTPS。
- 本地 MCP：展示完整命令并取得明确同意。
- 把每个 MCP 服务器当作独立信任域；按任务/技能需要连接，而不是按默认；按 Agent 白名单服务器与工具；核算每次连接的 schema/结果注入成本；大结果溢出到工件存储。绝不为省成本绕过 MCP 的权限/审计。
